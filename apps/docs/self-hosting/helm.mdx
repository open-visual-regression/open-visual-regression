title: Helm
description: Deploy OVR to Kubernetes with the published Helm chart.
---

The chart deploys the OVR `web` and `worker` images, plus a migration Job that runs before each install and upgrade. Postgres, Redis, and object storage are yours to provide.

## Requirements

- Kubernetes 1.23+, any distribution.
- Helm 3.8+, and [cosign](https://docs.sigstore.dev/cosign/installation/) to verify chart signatures.
- Postgres, a Redis-compatible instance, and an S3-compatible bucket reachable from the cluster. Run them in-cluster with their own charts ([Valkey](https://valkey.io/valkey-helm/), [RustFS](https://charts.rustfs.com), [CloudNativePG](https://cloudnative-pg.io)) or use managed services.
- An ingress controller, to reach the dashboard from outside the cluster. [Traefik](https://traefik.io) is the tested default. Avoid ingress-nginx, which is retired and unmaintained.

## Install

```sh
helm install ovr oci://ghcr.io/open-visual-regression/charts/ovr \
  --version X.Y.Z \
  --namespace ovr --create-namespace \
  -f my-values.yaml
```

Chart versions match OVR versions: `--version 1.4.2` installs OVR 1.4.2. There's no floating tag, so always pass `--version`. Published versions are listed on the [GHCR package page](https://github.com/orgs/open-visual-regression/packages/container/package/charts%2Fovr).

Verify a chart before installing it:

```sh
cosign verify ghcr.io/open-visual-regression/charts/ovr:X.Y.Z \
  --certificate-identity-regexp '^https://github.com/open-visual-regression/open-visual-regression/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```

`helm test ovr` checks the web readiness endpoint through its Service.

## Required values

| Value | Description |
| --- | --- |
| `env.baseUrl` | Public URL OVR is served at |
| `auth.betterAuthSecret` | Signs sign-in sessions. Generate with `openssl rand -base64 32` |
| `auth.gitTokenEncryptionKey` | Encrypts the git provider tokens projects store. Generate with `openssl rand -base64 32` |
| `database.url` | Postgres connection string |
| `redis.url` | Redis connection string |
| `storage.bucket` / `storage.region` | Bucket name and region. The bucket must already exist |

Each value is described in [Environment variables](/reference/environment-variables#required).

To keep secrets out of your values file, set `existingSecret` to a Secret you manage, by hand or with a tool like Sealed Secrets or External Secrets. It needs the keys `DATABASE_URL`, `REDIS_URL`, `BETTER_AUTH_SECRET`, `OVR_GIT_TOKEN_ENCRYPTION_KEY`, `STORAGE_ACCESS_KEY`, and `STORAGE_SECRET_KEY`, plus `github-app-private-key.pem` if you use a GitHub App.

To sign people in through an SSO proxy in front of OVR instead of OVR's own passwords, set `auth.mode` and `auth.trustedProxy`. See [SSO](/self-hosting/sso).

To publish commit statuses as a GitHub App instead of with each project's access token, set `githubApp.appId` and `githubApp.privateKey`. See [GitHub App](/self-hosting/github-app).

## Object storage

Any S3-compatible service works: AWS S3, Cloudflare R2, RustFS, MinIO, and others.

| Value | Description |
| --- | --- |
| `storage.endpoint` | Internal address the app uses to reach storage. Empty for AWS S3. |
| `storage.publicEndpoint` | Address used in presigned URLs handed to CI and browsers. Empty for AWS S3. |
| `storage.forcePathStyle` | `true` for RustFS, MinIO, R2, and most self-hosted services. `false` for AWS S3. |
| `storage.accessKey` / `storage.secretKey` | Static credentials. Leave empty to use a cloud IAM role instead. |

Empty credentials fall through to the provider's default credential chain, so annotating the ServiceAccount is enough to use IRSA or Workload Identity:

```yaml
serviceAccount:
  annotations:
    eks.amazonaws.com/role-arn: arn:aws:iam::111122223333:role/ovr
```

## Sizing

CPU and memory grow with how many captures run at once. Each worker runs `worker.concurrency` captures at a time, two by default, each in its own browser. The chart sets no requests or limits, so set `worker.resources` from what you see under load.

| Value | Default | Description |
| --- | --- | --- |
| `worker.concurrency` | `2` | Captures a worker runs at once |
| `worker.shmSize` | `1Gi` | Shared memory for the browser |
| `worker.terminationGracePeriodSeconds` | `180` | How long a stopping worker gets to finish the snapshots it's capturing |
| `web.resources` / `worker.resources` | `{}` | Resource requests and limits |
| `web.updateStrategy` / `worker.updateStrategy` | `RollingUpdate` | Needs room for two copies of a pod during a rollout. Use `Recreate` if the cluster doesn't have it |

The worker's other settings, like the capture queue and retention, are in [Environment variables](/reference/environment-variables) with their Helm values. The worker's caches count against the pod's ephemeral storage.

## Expose it

Set `web.ingress.enabled: true` and `web.ingress.host`, plus `web.ingress.className` and `web.ingress.annotations` for your controller and TLS setup. Or use `kubectl port-forward`, see the `helm install` output for the command.

With `web.ingress.tls` set, `web.ingress.redirectHttps` (default `true`) redirects HTTP to HTTPS. Implemented for `className: traefik` and `className: nginx`. Configure the redirect yourself on other controllers.

Turn off response buffering for the dashboard on your ingress controller, or pages wait for all their data before they show anything. nginx turns it off on its own.

## Scaling

All off by default.

| Value | Description |
| --- | --- |
| `web.autoscaling` | CPU-based HorizontalPodAutoscaler. Requires `web.resources.requests`, since targets are a percentage of the request. |
| `worker.keda` | Queue-depth autoscaling via a [KEDA](https://keda.sh) `ScaledObject`. Requires KEDA in the cluster, the chart does not install it. Mutually exclusive with `worker.autoscaling`. |
| `web.podDisruptionBudget` / `worker.podDisruptionBudget` | Set exactly one of `minAvailable` or `maxUnavailable`. `minAvailable: 1` against a single replica blocks node drains. |
| `web.topologySpreadConstraints` / `worker.topologySpreadConstraints` | Passed through verbatim. Include a `labelSelector`, the chart does not inject one. |
| `web.priorityClassName` / `worker.priorityClassName` | Passed through verbatim. |

Scale the worker on queue depth rather than CPU. A pod holding an idle browser between snapshots looks unloaded while it is busy, so a CPU-based autoscaler will scale it away mid-capture. KEDA scales on waiting capture groups:

```yaml
worker:
  keda:
    enabled: true
    maxReplicaCount: 8
    cooldownPeriod: 600
    redisAddress: valkey:6379
    listLength: 4
```

The generated trigger only sees work queued under the `fifo` [capture queue policy](/reference/environment-variables#capture-queue), so with it the chart uses `fifo` and refuses `deadline` and `round-robin`. To keep `deadline`, replace the trigger through `worker.keda.triggers`, for example with the [Prometheus trigger](/self-hosting/metrics#autoscale-workers).

If Redis needs a password or TLS, point `worker.keda.authenticationRef` at a KEDA [`TriggerAuthentication`](https://keda.sh/docs/latest/scalers/redis-lists/#authentication-parameters). `worker.keda.triggers` replaces the generated trigger entirely.

<Warning>
`cooldownPeriod` must outlast the longest capture group, and `worker.terminationGracePeriodSeconds` must cover the in-flight snapshot on top of that. Otherwise a scale-down stops a worker mid-capture.
</Warning>

## Network policies

`networkPolicy.enabled` adds a policy per component. The worker gets deny-all ingress. The web pod admits traffic on its port from anywhere in the cluster, narrow that with `networkPolicy.web.from`.

Egress always allows DNS, and is otherwise unrestricted. Setting `networkPolicy.egress` replaces that default entirely, so it must list everything the pods reach: Postgres, Redis, object storage, and your git provider.

## Metrics

Set `metrics.enabled` to serve metrics from the web and worker pods for Prometheus, Datadog, or another monitoring tool. With the Prometheus Operator, the chart can also create the scrape config, alerting rules, and a Grafana dashboard. See [Metrics](/self-hosting/metrics).

## Security

Containers run as UID/GID `1001`, drop all capabilities, and disable privilege escalation.

The worker omits the `RuntimeDefault` seccomp profile that the other pods set, because its browser sandbox needs unprivileged user namespaces that the profile blocks. The worker is therefore not admissible to a Pod Security Admission `restricted` namespace as shipped. To run it in one, set `worker.containerSecurityContext.seccompProfile` and disable the browser sandbox.

## Update

```sh
helm upgrade ovr oci://ghcr.io/open-visual-regression/charts/ovr \
  --version X.Y.Z \
  --namespace ovr \
  -f my-values.yaml
```

The migration Job runs before the new pods start. Each chart version pins the matching OVR release, so `--version` decides which release runs.
