---
title: External hosts
description: Let captures load images, fonts, and other assets from hosts outside the Storybook build.
---

Captures load the Storybook build and nothing else. A request to any other host fails, so a
story can't fetch live data or reach a service on the worker's network, and a slow third
party can't make its screenshots flaky.

That includes requests a service worker makes. If your stories mock APIs with
[msw](https://mswjs.io), requests it doesn't mock pass through it to the network and are
blocked too.

When a story needs assets from another host, like an image CDN or a web font service, list
that host so captures can load it.

<Note>
Since worker 0.16.1, captures block every external host, including requests a service worker
passes through. Before that, requests a service worker made reached the network. If remote
images and fonts in your stories started capturing as spinners, broken images, or fallback
fonts after upgrading, list their hosts here.
</Note>

## Allow a host

Set `OVR_CAPTURE_ALLOWED_HOSTS` on the worker to a comma-separated list:

```sh
OVR_CAPTURE_ALLOWED_HOSTS=images.example.com,fonts.googleapis.com,fonts.gstatic.com
```

With the Helm chart, set `worker.capture.allowedHosts`:

```yaml
worker:
  capture:
    allowedHosts:
      - images.example.com
      - fonts.googleapis.com
      - fonts.gstatic.com
      - "*.cdn.example.com"
```

The worker reads the list when it starts and won't start if an entry is invalid. Allowed
hosts load the same way the Storybook build does: captures wait for them before taking the
screenshot, including when a service worker answers the request.

The list applies to every project the worker captures. Only the people running the worker
can widen what captures reach, so a project can't use its stories to reach hosts on the
worker's network.

## Entry format

| Entry | Allows |
| --- | --- |
| `images.example.com` | That host on any port |
| `images.example.com:8443` | That host on port 8443 only |
| `*.example.com` | Every subdomain of `example.com`, not `example.com` itself. List both to allow both |
| `10.0.0.5`, `[2001:db8::1]:443` | An IP address, with an optional port. Wrap IPv6 addresses in brackets |

List hosts, not URLs: no scheme, path, or `*` on its own.

Each browser applies the list a little differently:

- **Chromium** matches entries exactly as described above.
- **WebKit** also lets `images.example.com` load its subdomains, and `*.example.com` load
  `example.com` itself.
- **Firefox** matches by hostname suffix and can't limit an entry to one port, so
  `images.example.com:8443` allows `images.example.com` on every port in Firefox. The worker
  logs a warning for each such entry when it starts.

## Find what was blocked

A blocked request fails with a generic network error, like `net::ERR_FAILED`. So when a
capture blocks requests, the snapshot's logs also get one warning that names each host it
blocked:

```
Blocked requests to fonts.gstatic.com, images.example.com. Captures only load the Storybook build and the hosts in OVR_CAPTURE_ALLOWED_HOSTS.
```

Open a snapshot that diffs unexpectedly and check its logs for this line to see which hosts
to allow.

## Network policies

The allowlist only lets the browser try the request. The worker pod still needs a network
route to the host. If you set `networkPolicy.egress` in the Helm chart, include the allowed
hosts in it.

## Local captures

[`ovr capture storybook`](/cli/capture-storybook) blocks external hosts the same way. Give
it the same list with `capture.allowedHosts` in [`ovr.config`](/configuration/config) or
the `--allowed-hosts` flag, so stories capture on your machine as they do on the server.
