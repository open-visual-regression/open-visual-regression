---
title: Docker Compose
description: Run OVR with Docker Compose, from fully bundled to fully external.
---

OVR runs as two containers, `web` and `worker`, plus a `migrate` container that runs schema migrations once at startup and exits. Point it at a Postgres database, a Redis-compatible instance, and an S3-compatible bucket, bundled alongside it or already running elsewhere, and it's up.

## Requirements

- Docker Engine with the Compose plugin (`docker compose`, not the older standalone `docker-compose`)
- 2 vCPU / 4 GB RAM is enough for a small team. The worker is the heaviest part since it drives headless Chromium through Playwright. Lower `OVR_CAPTURE_GROUP_CONCURRENCY` if you're tight on resources.
- Disk for whatever you bundle: Postgres data, Redis/Valkey data, object storage data, and the worker's local build cache (2 GB by default, see `OVR_STORYBOOK_CACHE_BYTES` below)

## Quick start

This runs everything, including Postgres, Redis, and object storage, in containers. No external accounts needed.

Create `docker-compose.yml`:

```yaml
x-app-env: &app-env
  DATABASE_URL: postgresql://${DATABASE_USER:-postgres}:${DATABASE_PASSWORD:-postgres}@db:5432/${DATABASE_NAME:-open_visual_regression}
  REDIS_URL: redis://valkey:6379
  STORAGE_ENDPOINT: http://rustfs:9000
  STORAGE_PUBLIC_ENDPOINT: ${STORAGE_PUBLIC_ENDPOINT:-http://localhost:${STORAGE_PORT:-9000}}
  STORAGE_REGION: ${STORAGE_REGION:-us-east-1}
  STORAGE_BUCKET: ${STORAGE_BUCKET:-ovr}
  STORAGE_ACCESS_KEY: ${STORAGE_ACCESS_KEY:-rustfsadmin}
  STORAGE_SECRET_KEY: ${STORAGE_SECRET_KEY:-rustfsadmin}
  LOG_LEVEL: ${LOG_LEVEL:-info}
  BASE_URL: ${BASE_URL:-http://localhost:3000}
  OVR_GIT_TOKEN_ENCRYPTION_KEY: ${OVR_GIT_TOKEN_ENCRYPTION_KEY:?set OVR_GIT_TOKEN_ENCRYPTION_KEY in your .env}

services:
  db:
    image: postgres:17-alpine
    restart: always
    environment:
      POSTGRES_DB: ${DATABASE_NAME:-open_visual_regression}
      POSTGRES_USER: ${DATABASE_USER:-postgres}
      POSTGRES_PASSWORD: ${DATABASE_PASSWORD:-postgres}
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -d ${DATABASE_NAME:-open_visual_regression} -U ${DATABASE_USER:-postgres}"]
      interval: 1s
      timeout: 5s
      retries: 10
    volumes:
      - pgdata:/var/lib/postgresql/data

  valkey:
    image: valkey/valkey:8-alpine
    restart: always
    healthcheck:
      test: ["CMD", "valkey-cli", "ping"]
      interval: 1s
      timeout: 5s
      retries: 10
    volumes:
      - valkeydata:/data

  rustfs:
    image: rustfs/rustfs:latest
    restart: always
    environment:
      RUSTFS_ACCESS_KEY: ${STORAGE_ACCESS_KEY:-rustfsadmin}
      RUSTFS_SECRET_KEY: ${STORAGE_SECRET_KEY:-rustfsadmin}
      RUSTFS_ADDRESS: 0.0.0.0:9000
      RUSTFS_VOLUMES: /data
    ports:
      - ${STORAGE_PORT:-9000}:9000
      - ${STORAGE_CONSOLE_PORT:-9001}:9001
    volumes:
      - rustfsdata:/data

  createbuckets:
    image: amazon/aws-cli
    depends_on:
      rustfs:
        condition: service_started
    environment:
      AWS_ACCESS_KEY_ID: ${STORAGE_ACCESS_KEY:-rustfsadmin}
      AWS_SECRET_ACCESS_KEY: ${STORAGE_SECRET_KEY:-rustfsadmin}
      AWS_DEFAULT_REGION: ${STORAGE_REGION:-us-east-1}
    entrypoint:
      - /bin/sh
      - -c
      - |
        until aws --endpoint-url http://rustfs:9000 s3 ls >/dev/null 2>&1; do sleep 2; done
        aws --endpoint-url http://rustfs:9000 s3 mb "s3://${STORAGE_BUCKET:-ovr}" 2>/dev/null || true
    restart: "no"

  migrate:
    image: ghcr.io/open-visual-regression/worker:latest
    command: ["node", "dist/migrate.js"]
    depends_on:
      db:
        condition: service_healthy
    environment:
      <<: *app-env
    restart: "no"

  web:
    image: ghcr.io/open-visual-regression/web:latest
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
      valkey:
        condition: service_healthy
      migrate:
        condition: service_completed_successfully
      createbuckets:
        condition: service_completed_successfully
    environment:
      <<: *app-env
      BETTER_AUTH_SECRET: ${BETTER_AUTH_SECRET:?set BETTER_AUTH_SECRET in your .env}
      PORT: ${WEB_PORT:-3000}
    ports:
      - ${WEB_PORT:-3000}:${WEB_PORT:-3000}

  worker:
    image: ghcr.io/open-visual-regression/worker:latest
    restart: unless-stopped
    depends_on:
      db:
        condition: service_healthy
      valkey:
        condition: service_healthy
      migrate:
        condition: service_completed_successfully
      createbuckets:
        condition: service_completed_successfully
    environment:
      <<: *app-env
      OVR_CAPTURE_GROUP_CONCURRENCY: ${OVR_CAPTURE_GROUP_CONCURRENCY:-2}
    volumes:
      - workertmp:/tmp

volumes:
  pgdata:
  valkeydata:
  rustfsdata:
  workertmp:
```

Create `.env` next to it:

```sh
# Required, generate each with: openssl rand -base64 32
BETTER_AUTH_SECRET=
OVR_GIT_TOKEN_ENCRYPTION_KEY=

# Public URL you'll reach the app at
BASE_URL=http://localhost:3000
```

Then start it:

```sh
docker compose up -d
```

Visit `BASE_URL` (`http://localhost:3000` by default). First run walks you through creating an organization and admin account.

## Environment variables

### Required

| Variable | Description |
| --- | --- |
| `BETTER_AUTH_SECRET` | Signs auth sessions. Generate with `openssl rand -base64 32`. |
| `OVR_GIT_TOKEN_ENCRYPTION_KEY` | Encrypts stored git provider tokens at rest. Must decode to 32 bytes: `openssl rand -base64 32`. Rotating it invalidates every stored token, they'll need to be re-entered. |
| `BASE_URL` | Public URL the app is served from. Defaults to `http://localhost:3000`, change it if you're not on localhost. |

### Database

| Variable | Description |
| --- | --- |
| `DATABASE_URL` | `postgresql://` connection string. The quick start above derives this from `DATABASE_NAME` / `DATABASE_USER` / `DATABASE_PASSWORD` instead, set it directly to use an external Postgres. |

### Redis

| Variable | Description |
| --- | --- |
| `REDIS_URL` | `redis://` or `rediss://` connection string. Backs the build queue, any Redis-compatible service works (Valkey, Redis, Upstash, ElastiCache, Memorystore). |

### Object storage

Any S3-compatible service works: AWS S3, Cloudflare R2, Backblaze B2, RustFS, MinIO, and others.

| Variable | Description |
| --- | --- |
| `STORAGE_BUCKET` | Bucket name. Must already exist, OVR doesn't create it for you against an external service. |
| `STORAGE_REGION` | Bucket region. |
| `STORAGE_ACCESS_KEY` / `STORAGE_SECRET_KEY` | Credentials. Leave both unset on AWS to use the default credential chain (IAM role, instance profile) instead of static keys. |
| `STORAGE_ENDPOINT` | Internal address the app uses to reach storage. Leave unset for AWS S3. |
| `STORAGE_PUBLIC_ENDPOINT` | Address baked into presigned URLs handed to CI and browsers. Leave unset for AWS S3. |
| `STORAGE_FORCE_PATH_STYLE` | `true` for RustFS, MinIO, R2, and most self-hosted S3-compatible services. `false` for AWS S3. |

### Optional tuning

| Variable | Default | Description |
| --- | --- | --- |
| `LOG_LEVEL` | `info` | Log verbosity. |
| `LOG_FILE_PATH` | unset | Log to a file instead of stdout. |
| `OVR_CAPTURE_GROUP_CONCURRENCY` | `2` | How many capture groups the worker processes in parallel. Each one drives its own headless browser, lower this on constrained hardware. |
| `OVR_CAPTURE_GROUP_SIZE` | `10` | Snapshots per capture group. |
| `OVR_REAPER_STALE_MINUTES` | `30` | Minutes before a stalled capture job is requeued. |
| `OVR_STORYBOOK_CACHE_BYTES` | `2147483648` (2 GB) | Max size of the worker's local Storybook build cache. |

### Ports, images, and container user

`WEB_PORT`, `DATABASE_PORT`, `REDIS_PORT`, `STORAGE_PORT`, and `STORAGE_CONSOLE_PORT` control host-side port mappings for whatever you bundle. `IMAGE_PREFIX` / `IMAGE_TAG` pin a specific release instead of `latest`. `PUID` / `PGID` match the container user to your host user, useful if you mount volumes you also access from the host.

## Using external services

Swap any bundled dependency for one you already run, self-hosted or managed, by removing its container from `docker-compose.yml` and pointing the matching variable at it instead:

| To use your own | Remove these services | Set |
| --- | --- | --- |
| Postgres | `db` | `DATABASE_URL` |
| Redis | `valkey` | `REDIS_URL` |
| Object storage | `rustfs`, `createbuckets` | `STORAGE_BUCKET`, `STORAGE_REGION`, `STORAGE_ACCESS_KEY`, `STORAGE_SECRET_KEY`, and `STORAGE_ENDPOINT` / `STORAGE_PUBLIC_ENDPOINT` / `STORAGE_FORCE_PATH_STYLE` for anything other than AWS S3 |

Also drop the removed service from `depends_on` on `migrate`, `web`, and `worker`, and drop its volume from the `volumes:` block at the bottom. For object storage, create the bucket yourself first, external setups don't create it for you.

Ready-made Compose files for each combination are in the repo, pull one down instead of assembling it by hand if you'd rather:

- [`fully-self-hosted`](https://github.com/open-visual-regression/open-visual-regression/tree/main/examples/docker/fully-self-hosted) — everything bundled, matches the quick start above
- [`external-postgres`](https://github.com/open-visual-regression/open-visual-regression/tree/main/examples/docker/external-postgres) — your own Postgres, Redis and storage bundled
- [`external-redis`](https://github.com/open-visual-regression/open-visual-regression/tree/main/examples/docker/external-redis) — your own Redis, Postgres and storage bundled
- [`external-storage`](https://github.com/open-visual-regression/open-visual-regression/tree/main/examples/docker/external-storage) — your own bucket, Postgres and Redis bundled
- [`fully-external`](https://github.com/open-visual-regression/open-visual-regression/tree/main/examples/docker/fully-external) — Postgres, Redis, and storage all managed elsewhere, only `web` and `worker` run

## Update

```sh
# edit IMAGE_TAG in .env to the release you want, then:
docker compose pull
docker compose up -d
```

## Back up your data

Everything self-hosted lives in named Docker volumes (Postgres data, Redis/Valkey data, object storage data, the worker's temp cache). Back those up the way you'd back up any container volume, there's no separate export step.
