OVR catches visual changes to your UI before they merge. It captures screenshots of your components on every commit, compares them with the last approved version, and asks a person to review anything that changed. Pull requests wait until the changes are approved.

It runs on your own infrastructure: a web app for reviewing, workers that capture screenshots in real browsers, and a CLI that your CI runs. Today, OVR captures [Storybook](/storybook/overview).

## Why visual testing

Unit tests check what a component does, not how it looks. A component can pass every test and still ship with broken spacing, a clipped label, or a layout that only breaks at one screen width. That's easy to miss in a code review, whether a person or an AI agent wrote the change.

Comparing screenshots is deterministic. Every component, at every viewport, on every commit, OVR shows exactly what changed, and a reviewer decides whether that was the intent.

## What you get

- **No test files to write.** OVR captures the components you already have.
- **A review step.** Changes above the diff threshold wait for a reviewer, and [enough approvals](/manage/projects#settings) let the pull request through.
- **Status checks on GitHub.** Each build posts a [commit status](/manage/git-status-checks), so branch protection can require a review.
- **Your infrastructure.** Postgres, Redis, and any S3-compatible storage, run yourself or as managed services.
