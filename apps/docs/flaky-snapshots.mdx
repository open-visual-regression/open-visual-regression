A snapshot is flaky when the same code doesn't produce the same image every time, for example because an animation is caught at a different frame or data loads in a different order. A flaky snapshot shows up as a change to review even when nothing changed.

When flaky detection is on, OVR watches each snapshot across recent builds on the main branch, and marks it flaky when it:

- keeps returning to an image it had before,
- looks different for the same commit, or
- changes on most builds.

A flaky snapshot has a **flaky** badge on the build page and on the snapshot page, in every build, including pull requests and older builds. To review only flaky snapshots, pick **flaky** in the **flags** filter on the build page, or run `ovr snapshots list <buildId> --flag flaky`.

To make a flaky snapshot stable, see [Stable screenshots](/storybook/stable-screenshots).

## Turn on detection

Flaky detection is off by default. An admin turns it on under **Settings → Jobs**, and can set:

- how often snapshots are checked, as a cron schedule. Twice a day, at 7am and 7pm, by default.
- how many recent main-branch builds are considered. 30 by default.

Changes apply on the next scheduled run.

Detection only uses builds captured after it was turned on, so it takes a few main-branch builds before anything is marked flaky.
