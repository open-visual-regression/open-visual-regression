---
title: Authentication
description: Project API keys and personal access tokens, and which commands take which.
---

Every command reads its credential from `OVR_API_KEY`:

```sh
export OVR_API_KEY=...
```

OVR has two kinds of credentials, and each command takes one of them:

| Credential | Create it under | Used by |
| --- | --- | --- |
| Project API key | The project's **settings** page, under **api keys** | `ovr upload storybook` |
| Personal access token | **Settings → Access tokens** | `ovr builds`, `ovr snapshots`, and `ovr diffs` |

An API key belongs to one project and can only upload builds to it. An admin creates it.

An access token belongs to you. It can read builds in every project you can see, and it can only do what your role allows: a viewer's token can't cancel, rebuild, approve, or reject, whatever permissions it has.

## Access token permissions

Every access token can read builds (`builds:read`). When you create one, you can also give it:

| Permission | Lets the token |
| --- | --- |
| `builds:write` | Cancel and rebuild builds, and rebuild some of a build's snapshots |
| `reviews:write` | Approve or reject a snapshot, or every snapshot in a build |

Removing a vote is only possible in the web app.

You can't change a token's permissions after creating it. Create a new token and revoke the old one.
