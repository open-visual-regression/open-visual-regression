---
title: Authentication
description: Project API keys vs. personal access tokens, and which commands take which.
---

Every command reads its credential from `OVR_API_KEY`:

```sh
export OVR_API_KEY=...
```

OVR has two kinds of tokens. A command accepts only one kind and rejects the other.

| Token | Created from | Used by |
|-------|--------------|---------|
| Project API key | A project's settings page | `ovr upload storybook` |
| Personal access token | Your account's access tokens settings page | every `ovr builds`, `ovr snapshots` and `ovr diffs` command |

A personal access token belongs to you, not a project — it can read builds across every project you have access to.

## Access token permissions

Every personal access token has `builds:read`, which lets it read builds. When you create one, you can also give it:

| Permission | Lets the token |
|------------|----------------|
| `builds:write` | Cancel a build, rebuild a build, and rebuild some of a build's snapshots |
| `reviews:write` | Approve or reject a snapshot, or every snapshot in a build. Removing a vote is only possible in the web app |

A token acts as you, so it can only do what your role allows: a viewer's token can't cancel, rebuild, approve or reject, whatever it was granted. Permissions are fixed when the token is created. To change them, create a new token and revoke the old one.
