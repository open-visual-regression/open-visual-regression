---
title: ovr upload storybook
description: Upload a Storybook build for OVR to capture and compare.
---

Uploads a Storybook 8.5+ static build (the output of `storybook build`) as a new build. Takes a [project API key](/cli/authentication), and the [global flags](/cli/installation#global-flags).

```sh
ovr upload storybook \
  --dir storybook-static \
  --server-url https://ovr.example.com \
  --branch "$BRANCH" \
  --commit "$COMMIT_SHA" \
  --name "$(git log -1 --pretty=%s)" \
  --author "$(git log -1 --pretty=%an)"
```

## Flags

| Flag | Required | Default | Description |
| --- | --- | --- | --- |
| `-d, --dir <path>` | yes | | Path to the Storybook static build |
| `--branch <name>` | yes | | Branch name |
| `--commit <sha>` | yes | | Commit SHA |
| `--name <name>` | no | | Build name, such as the commit message |
| `--author <author>` | no | | Commit author |
| `--wait` | no | `false` | Wait for the build's result before exiting |
| `--timeout <seconds>` | no | `600` | How long `--wait` waits |
| `--only-affected` | no | `false` | Only capture the stories a change can affect. See [below](#only-affected-stories) |

Without `--wait`, the command prints the build's URL and exits as soon as the upload is done. With `--wait`, it waits for OVR to capture and compare the build, and its [exit code](/cli/installation#exit-codes) tells your CI whether the build passed.

## Only affected stories

`--only-affected` captures only the stories a change can affect. Every other story is listed on the build as skipped and keeps its baseline. A story with no baseline yet is always captured.

It needs:

- Storybook built with `--stats-json` by the Vite, Webpack 5, or Rspack (`storybook-builder-rsbuild`) builder, and `ovr` run from the directory it was built in.
- The full git history. In GitHub Actions, check out with `fetch-depth: 0`.
- A successful build on the project's main branch in the commit's history to compare against.

When any of these is missing, or the change can affect every story, OVR captures every story and the CLI says why. Changes that affect every story include Storybook and build configuration, dependencies the Storybook uses, and global styles. To mark other files that affect stories without being imported, use [`onlyAffected`](/configuration/config#only-affected) in `ovr.config`.

Use it for pull requests, and capture every story on the main branch.

<Accordion title="Supported lockfiles">

When a lockfile changes, OVR checks which packages changed. It captures every story only if one of them is bundled into the Storybook or is a build tool.

| Package manager | Lockfile | Versions |
| --- | --- | --- |
| Yarn | `yarn.lock` | Yarn 1, and Yarn 2 and later |
| pnpm | `pnpm-lock.yaml` | pnpm 8 and later |
| npm | `package-lock.json`, `npm-shrinkwrap.json` | npm 7 and later |

A change to any other lockfile, such as Bun's `bun.lock`, captures every story.

</Accordion>

## CI example

```yaml
- uses: actions/checkout@v4
  with:
    # Build the pull request's own commit, with the history OVR needs to find its merge base.
    ref: ${{ github.event.pull_request.head.sha || github.sha }}
    fetch-depth: 0

- name: Build Storybook
  run: pnpm build-storybook

- name: Upload to OVR
  env:
    OVR_API_KEY: ${{ secrets.OVR_API_KEY }}
  run: |
    npx @open-visual-regression/cli upload storybook \
      --dir storybook-static \
      --server-url https://ovr.example.com \
      --branch "${{ github.head_ref || github.ref_name }}" \
      --commit "${{ github.event.pull_request.head.sha || github.sha }}" \
      --name "$(git log -1 --pretty=%s)" \
      --author "$(git log -1 --pretty=%an)"
```

On pull requests, GitHub checks out a merge of the pull request into its base branch by default. Checking out the pull request's own commit makes the screenshots match the commit OVR records, and lets OVR compare the branch against main [as it was when the branch was cut](/baselines#branch-builds).

<Note>
  This command used to be called `ovr snapshot storybook`. The old name still works but prints a deprecation notice, and will be removed in a future release.
</Note>
