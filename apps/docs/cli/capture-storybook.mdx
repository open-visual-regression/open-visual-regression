---
title: ovr capture storybook
description: Capture stories on your machine to check their screenshots are stable.
---

Captures stories from a Storybook 8.5+ static build on your machine, with the same viewports, story parameters, and diff threshold as a build, and checks that each one looks the same every time. Use it to reproduce a flaky snapshot. Nothing is uploaded, so it needs no credential.

It needs [Playwright](https://playwright.dev) and a browser installed alongside the CLI:

```sh
npm install --save-dev playwright
npx playwright install chromium
```

```sh
ovr capture storybook --dir storybook-static --story components-dialog--open --repeat 10
```

## Flags

| Flag | Required | Default | Description |
| --- | --- | --- | --- |
| `-d, --dir <path>` | yes | | Path to the Storybook static build |
| `--story <id...>` | no | every story | Stories to capture |
| `--viewport <name...>` | no | each story's viewports | Only capture these viewports |
| `--repeat <count>` | no | `1` | Times to capture each story and viewport, 1–100 |
| `--out <dir>` | no | | Save each distinct image to this directory |
| `--cpu-throttle <rate>` | no | | Slow the CPU down by this factor. Chromium only |
| `--executable-path <path>` | no | | Browser to launch instead of Playwright's |
| `-c, --config <path>` | no | `ovr.config` | Path to `ovr.config` |
| `--json` | no | | Print JSON instead of a table |

## Output

```
TARGET                      BROWSER   VIEWPORT  RUNS  IMAGES  MAX DIFF%  RESULT
components-dialog--open     chromium  desktop   10    3       2.08       unstable
components-button--primary  chromium  desktop   10    1       0.00       stable

components-dialog--open (desktop): 6x, 0.00% different: out/components-dialog--open--desktop--1f0c2a9b3d4e.png
components-dialog--open (desktop): 3x, 2.08% different: out/components-dialog--open--desktop--8a7e6d5c4b3a.png
components-dialog--open (desktop): 1x, 1.12% different: out/components-dialog--open--desktop--0b1c2d3e4f5a.png

1 of 2 captures stayed within their diff threshold on every run.
```

`IMAGES` counts the distinct images across runs, and `MAX DIFF%` is the largest difference from the first run. A capture is `stable` when every run is within the story's `diffThreshold`, `unstable` when a run goes over it, and `error` when the story failed to render. With [`blockExternalRequests`](/reference/ovr-config#blocking-external-requests) set, each story also lists the hosts it requested that were blocked.

The command exits `1` if any capture is unstable or failed, so it can run in CI.

<Note>
  Fonts and the operating system make screenshots on your machine differ slightly from a build's. Compare runs with each other, not with images from a build.
</Note>
