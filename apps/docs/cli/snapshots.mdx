Takes an [access token](/manage/api-keys-and-tokens#access-tokens). Every subcommand also takes the [global flags](/cli/overview#global-flags).

## `ovr snapshots counts`

```sh
ovr snapshots counts <buildId>
```

Counts the build's snapshots by status, to see the shape of a build before listing it:

```
STATUS        COUNT
unchanged     41
needs_review  3
error         1
TOTAL         45
```

## `ovr snapshots list`

```sh
ovr snapshots list <buildId> --status needs_review
```

| Flag | Description |
| --- | --- |
| `--status <status...>` | Only snapshots with these statuses |
| `--browser <name...>` | Only snapshots captured in these browsers |
| `--viewport <name...>` | Only snapshots captured at these viewports |
| `--flag <flag...>` | Only snapshots with these flags |
| `--search <text>` | Only snapshots matching this text |
| `--limit <count>` | Snapshots per page, 1–100. Defaults to `24` |
| `--cursor <cursor>` | Fetch the page after this cursor |
| `--all` | Fetch every page |

```
SNAPSHOT                              STATUS        STORY                        BROWSER   VIEWPORT           DIFF%  FLAGS
01a092d6-b0aa-71bf-9312-dd8ef48a22fb  needs_review  Components/Button / Primary  chromium  desktop 1280x800   1.23   flaky
```

`DIFF%` is the percentage of pixels that differ from the baseline. It's `-` when there was nothing to compare, because the snapshot is new or failed. A viewport that captures the full page shows its height as `full`.

`--status` takes `unchanged`, `auto_approved`, `approved`, `needs_review`, `rejected`, `error`, `canceled`, `skipped`, `queued`, and `processing`. `--flag` takes `flaky` for [flaky snapshots](/flaky-snapshots) and `warning` for snapshots whose page threw an uncaught error.

Pages work like [`ovr builds list`](/cli/builds#pagination).

## `ovr snapshots get`

```sh
ovr snapshots get <snapshotId>
```

| Flag | Description |
| --- | --- |
| `--download <dir>` | Save the snapshot image to this directory as `snapshot.png` |

Prints the snapshot's details, its flags, and anything it logged to the console while it was captured:

```
Snapshot: 01a092d6-b0aa-71bf-9312-dd8ef48a22fb
Status:   error
Story:    Components/Button / Primary
Browser:  chromium
Viewport: desktop 1280x800
Image:
Flags:    warning
Error:    story threw during render

Flags:
  warning: the page threw an uncaught error

Logs:
  [error] TypeError: Cannot read properties of undefined (2026-09-12T10:43:15Z)
```

## `ovr snapshots history`

```sh
ovr snapshots history <snapshotId>
```

| Flag | Description |
| --- | --- |
| `--branch <name>` | Branch to show. Defaults to the project's main branch |
| `--limit <count>` | Builds to show, 1–100. Defaults to `30` |

Shows the same snapshot across recent builds on a branch, newest first. Each distinct image gets a letter in the `IMAGE` column, so a snapshot that flips between two images is easy to spot:

```
SNAPSHOT                              BUILD                                 COMMIT   CREATED               STATUS         DIFF%  IMAGE
01a1266c-7f4e-732a-93ea-9bbc9e97f3df  01a1266c-55b5-7729-8e1f-1b7c625b364b  278382f  2026-10-10T15:20:11Z  auto_approved  1.48   C
01a11221-6061-71af-8a8a-56aad8d9a689  01a11221-4abe-7008-a90f-bf2c09b84f07  04b9a07  2026-10-08T09:02:45Z  auto_approved  2.07   B
01a111e5-ac09-730b-9714-616d7397e056  01a111e5-8050-772d-9b46-19088f018444  04b9a07  2026-10-08T08:13:30Z  auto_approved  2.12   A

Screenshot changed 2 times across the last 3 builds on main (3 distinct images).
```

## `ovr snapshots rebuild`

```sh
ovr snapshots rebuild <buildId> <snapshotId...>
ovr snapshots rebuild <buildId> --status error
```

| Flag | Description |
| --- | --- |
| `--status <status...>` | Rebuild snapshots with these statuses |
| `--browser <name...>` | Rebuild snapshots captured in these browsers |
| `--viewport <name...>` | Rebuild snapshots captured at these viewports |
| `--flag <flag...>` | Rebuild snapshots with these flags |
| `--search <text>` | Rebuild snapshots matching this text |

Captures some of a build's snapshots again, in the same build. Choose them by ID or with the same filters as [`ovr snapshots list`](#ovr-snapshots-list), but not both. Filters leave out snapshots that are still in progress or skipped. A snapshot you name by ID that can't be rebuilt fails the command. To capture the whole build again, use [`ovr builds rebuild`](/cli/builds#ovr-builds-rebuild).
